**Supplementary Fig. X | Repository-ordered, file-backed multi-Agent workflow for AMP benchmarking.** **a,** Repository-ordered execution graph. The project entry and configuration files invoke versioned role contracts under `agents/`, stage-specific Python engines and persisted artifacts under `data/`. Stage 1 transforms retrieved literature into a compact evidence pool, long-term memory and frozen model, dataset and metric recommendation tables. Stage 2 converts selected repositories and datasets into registered HPC executions or standardized manually imported predictions, followed by a common scientific evaluation protocol. Stage 3 transforms anonymous cross-dataset evidence into expert proposals, an independent review, a Chief decision and 50 round-specific decision records. **b,** Agent-definition layer. Functional roles are resolved to the actual Markdown files used for evidence compression, extraction, model and dataset scouting, metric design, repository inspection, code generation, bounded self-healing, independent auditing, consensus weighting and research-advisor synthesis. The arrows show the within-stage collaboration order; the three specialist proposals in Stage 3 are blind inputs to the Reviewer and Chief agents. **c,** Persisted intermediate-result ledger derived from the current project state. Stage 1 retains 2,365 retrieved papers in 304 evidence batches, 2,361 compacted papers in 241 chunks, 487 screened identities and 20 recommended models. Stage 2 contains three datasets, 62,310 sequences and 18 models with usable predictions. Stage 3 stores 12 eligible metrics, 50 round records, 600 metric-weight rows and 900 model-score rows before writing the terminal ranking, figures and future-directions report. Counts are descriptive artifact totals; the terminal ranking remains exploratory pending formal provenance, independence and homology gates. Source data are provided with the figure.
